# СКМ — информационный сайт

Сайт ООО «СКМ» на Next.js 16 показывает услуги, ориентировочные цены и способы связи. Публичных аккаунтов и оформления заказов нет. Приём заявок через «Связаться» включается при сборке и запуске с `NEXT_PUBLIC_CONTACT_REQUESTS_ENABLED=1`. По умолчанию видны форма и согласие, отправка закрыта.

## Разработка

```bash
npm ci
npm run dev
npm run lint
npm run build
```

Локальный адрес: `http://localhost:3000`.

## Содержимое и контакты

- Услуги и цены можно менять через закрытую панель `/admin`.
- Телефон и email заданы в `lib/site-config.ts`.
- Кнопки «Связаться» открывают форму заявки и прямые ссылки на телефон и почту. Сайт не загружает Jivo.
- Публичная политика обработки персональных данных находится на `/politika`. Она нужна, поскольку компания получает обращения с контактными данными по email и телефону. Перед публикацией юридических изменений проверьте её соответствие фактическим процессам ООО «СКМ».

## Администрирование

Вход на `/login` принимает шестизначный код из приложения «Пароли» или другого TOTP-аутентификатора. Задайте на сервере один `ADMIN_EMAIL`, секрет подписи `AUTH_SECRET` и секретную JSON-карту `ADMIN_TOTP_SECRETS` с ключом этого адреса. После проверки кода открывается отдельная проверка пароля панели. Сеансы, выпущенные ранее, потребуют повторного входа.

Команда `node scripts/generate-totp-key.mjs admin@example.test path/to/private-key.json` сохраняет новый ключ. Добавьте его в «Пароли» как ключ настройки. Храните секрет вне репозитория. Проверьте оба шага входа на стенде до переключения домена. При утере устройства замените ключ в настройках развёртывания.

Для проверки страны задайте `ADMIN_GEO_PROXY_TOKEN` случайной строкой base64url длиной от 43 символов. Доверенный прокси должен удалять входящие `X-SKM-Country` и `X-SKM-Geo-Token` и выставлять их заново. Страну прокси определяет по IP подключения своей базой геолокации. В токен подставляется серверное значение. Сайт допускает только `RU` с правильным токеном. Проверка охватывает вход, админку, API сессии и административные операции. При внешней геоблокировке проверьте вход через все альтернативные домены и прямые адреса приложения. До переключения проверьте прямое подключение из России и отказ из другой страны. Для доступа при включённом VPN добавьте домен в исключения, чтобы он использовал IP обычного подключения.

Публичная регистрация закрыта на уровне серверных действий. Старые страницы `/account` и `/checkout/*` удалены. Сохранённые ранее данные в базе не удаляются автоматически; их сроки хранения и удаление нужно определять отдельно.

Для PostgreSQL на том же сервере приложение поддерживает подключение через Unix-сокет. Например, `POSTGRES_URL=postgresql:///skm_site?host=/var/run/postgresql&user=skm_site` при запуске от отдельного системного пользователя `skm_site` и использовании peer-аутентификации.

Для подключения к удалённой PostgreSQL используйте адрес из её сертификата. Если сертификат выдан частным центром сертификации, укажите путь к его PEM-файлу в `POSTGRES_TLS_CA_FILE`.

Timeweb App Platform развёртывает ветку `main` Git-репозитория. После изменения кода требуется новый деплой из репозитория и проверка страниц сайта.

Если PostgreSQL остаётся на сервере компании, Timeweb запускает `npm run start:timeweb`. Переменные `SKM_DB_JUMP_HOST`, `SKM_DB_JUMP_FINGERPRINT`, `SKM_DB_HOME_FINGERPRINT`, `SKM_DB_JUMP_KEY_BASE64` и `SKM_DB_HOME_KEY_BASE64` задаются в защищённых настройках. Два отдельных SSH-ключа ограничивают переход до сервера и доступ до сокета PostgreSQL. Приложение начинает принимать запросы после проверки наличия таблицы услуг. Локальный TCP-порт моста привязан к 127.0.0.1. Если в старом окружении задано несколько адресов, `SKM_SITE_ADMIN_EMAIL` при запуске Timeweb передаёт в приложение только один выбранный адрес.

Режим Timeweb проверяет страну по локальной базе DB-IP Lite за ноябрь 2026 года ([DB-IP](https://db-ip.com/db/download/ip-to-country-lite), лицензия CC BY 4.0). Версия и SHA-256 заданы в `scripts/timeweb-geo.mjs`. В `SKM_TIMEWEB_PROXY_PEERS` задайте через запятую подтверждённые адреса непосредственных прокси Timeweb. На каждом домене проверьте, что прокси заменяет входящий `X-Forwarded-For` фактическим IP клиента. Проверка принимает один корректный IP и отклоняет неподтверждённые запросы. Между входным прокси и Next.js применяется служебный токен, который генерируется при запуске.
